01 · Method

What the script actually computes

Input is the filtered .h5ad from the QC step. Four operations, in order:

  1. Normalize: sc.pp.normalize_total(target_sum=1e4) then sc.pp.log1p — each cell's counts rescaled to the same total, then log-transformed. Raw counts are preserved in adata.layers["counts"] and the log-normalized-unscaled matrix in adata.raw, specifically so the scaled matrix used for PCA below doesn't contaminate later marker detection.
  2. HVG selection: sc.pp.highly_variable_genes(flavor="seurat_v3", n_top_genes=2000), run directly on the raw-counts layer. This is the modern default in current best-practice pipelines specifically because it models counts with their actual (non-Gaussian) noise structure rather than variance on already-transformed data.
  3. Scale: the HVG-subset matrix is zero-centered and unit-variance scaled, clipped at a max value of 10 (standard practice to stop a handful of extreme cells dominating the components below).
  4. PCA: 50 components via sc.tl.pca(svd_solver="arpack") on the scaled HVG subset.

04 · Why they differ

Where the disagreement comes from

The classic flavor computes dispersion (variance/mean) on log-transformed data, which compresses the dynamic range of highly-expressed genes non-linearly before variance is even measured. seurat_v3 instead fits a smooth mean-variance trend directly on raw counts and ranks genes by how far they deviate from that trend — closer to modeling the actual count noise (roughly Poisson/negative-binomial) rather than variance of a log-transformed proxy. In practice this means seurat_v3 tends to preferentially catch genes with strong dispersion at low mean expression that the log transform would flatten out, which is the likely source of most of the ~22% disagreement here.

Both are legitimate, widely used choices — the doc's default (seurat_v3) reflects current best-practice guidance rather than a claim that the classic flavor is wrong.

05 · Caveats

What this does not establish

Not yet validated on real project data

Same caveat as the QC report: PBMC3k is a droplet-based smoke test. HVG selection is dataset-dependent by design — the 78.2% overlap figure is specific to this dataset and will differ on real Evercode data, particularly since split-pool chemistry's count noise profile hasn't been directly compared against 10x's here.

Overlap isn't a correctness metric

A higher or lower overlap number doesn't by itself indicate one flavor is "more correct" — HVG selection feeds into a full downstream pipeline (PCA, clustering, annotation), and the only real validation is whether the resulting biology holds up, which is what the clustering and marker deep-dives check.
