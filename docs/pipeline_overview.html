01 · Scope

What this pipeline covers

Raw data comes off a next-generation sequencer (Illumina, primary case) as barcoded FASTQ from a Parse Evercode combinatorial-barcoding library — or as raw BCL files, converted with bcl2fastq --no-lane-splitting and no adapter-trimming sequence set (Parse warns trimming can eat into the Read 2 barcode region), using the Evercode kit's documented index sequences in the sample sheet. Because Parse's split-pool chemistry embeds cell identity across three rounds of barcoding rather than a single index read, standard demultiplexers (e.g. bcl2fastq alone, Cell Ranger) cannot resolve it beyond that point — raw FASTQ has to pass through Parse's own demultiplexing logic first, exposed via Trailmaker (cloud) or the underlying split-pipe command-line tool. Everything downstream of that hand-off is ours to design.

  • Input flexibility: Illumina short-read is the default target; the architecture keeps the sequencer-specific step isolated so a PacBio long-read run (full-length transcript capture) can be substituted without touching QC or downstream code.
  • Assay scope, phase 1: whole-transcriptome (gene expression) libraries only. Evercode TCR libraries share the same demultiplexing step but need a separate V(D)J/clonotype module — scoped as a follow-on once the GEX path is validated (see the TCR+GEX joint-modeling reference in Next Steps).
  • Compute: HiPerGator (UF Research Computing), everything scoped to /blue/esayour/puttawatsuphapru/ — no shared or system-wide paths — sized to the smallest SLURM allocation that finishes each step in reasonable time, no standing GPU reservations.

04 · Why Parse's demultiplexer is mandatory

Split-pool barcoding, not droplet indexing

Parse's chemistry is a commercial implementation of split-pool combinatorial barcoding: cells (or fixed nuclei) are distributed across a plate, barcoded, pooled, and re-split over several rounds, so each cell's identity is defined by a combination of barcodes read from within the cDNA read itself rather than a single per-sample index5. That is what makes the method scalable without microfluidics — but it also means the barcode-to-cell assignment logic is proprietary to the chemistry design, so generic demultiplexers can't be substituted in. Trailmaker (or its command-line counterpart, split-pipe) is the only correct place to perform that assignment; our pipeline treats it as a black-box, versioned upstream stage and starts its own logic at the resulting count matrix.

Trailmaker vs. split-pipe

Both run the identical barcode-correction/alignment/quantification logic — Trailmaker is Parse's hosted, no-code front end; split-pipe is the same pipeline as a Linux command-line tool. We're using Trailmaker as the primary path, but pipeline/split-pipe/ in this repo has a ready HiPerGator install script and SLURM job template as a scriptable, data-stays-on-cluster alternative. split-pipe itself is customer-gated software (Parse's Pipeline Download Request Form) and isn't vendored in the repo — only our setup scripts are.

05 · QC process and biological relevance

What each metric is actually catching

Rather than fixed cutoffs (e.g. a flat "10% mitochondrial" rule), the plan follows the adaptive, median-absolute-deviation (MAD) approach formalized in OSCA3 and implemented in the SCTK-QC pipeline1: thresholds are set per-sample from the data's own distribution, since "normal" values shift with cell type, tissue, and even chemistry version.

MetricWhat it measuresWhy it matters biologically
Total UMI counts / cell Sequencing depth and RNA content captured per barcode Too low usually means an under-sampled or degraded cell — but a fixed cutoff also discards genuinely small, transcriptionally quiet cells (e.g. naive lymphocytes), which is why an adaptive, sample-relative threshold is preferred over one flat number.
Genes detected / cell Transcriptome complexity captured per barcode Abnormally low tracks with empty or background barcodes; abnormally high — more genes than the depth would predict — is a classic multiplet signature.
Mitochondrial read % Proportion of reads mapping to the mitochondrial genome Elevated mito% reflects cytoplasmic RNA leaking out through a compromised membrane during dissociation/lysis — i.e. stressed or dying cells. Baseline varies by cell type (e.g. cardiomyocytes run naturally higher), so this is exactly the kind of metric MAD-based, per-sample thresholding is meant for.
Doublet / multiplet score Likelihood a barcode represents >1 cell In split-pool chemistry the mechanism differs from droplet platforms: instead of two cells sharing one droplet, two cells coincidentally receive the same barcode combination across the split-pool rounds. The expected rate scales with cells loaded per sub-library, so Parse-specific calibration is needed rather than reusing droplet-platform doublet-rate assumptions.
Ambient RNA / background Signal from lysed-cell RNA re-captured by unrelated barcodes In well-based combinatorial platforms this originates from cell lysis during the shared pooling/ligation steps rather than co-encapsulation with cell-free RNA in a droplet — the biological concern (contaminating signal diluting true cell identity) is the same, and decontamination approaches (e.g. DecontX-style) still apply conceptually.
Empty / background barcodes Barcode combinations with counts indistinguishable from noise The split-pool analog of "empty droplets" — statistical calls (knee-point / EmptyDrops-style, as used in SCTK-QC and QCatch1,2) separate real cells from combinatorial background before any per-cell metric is even computed.

Open decision

Exact MAD multiplier (commonly 3 or 5 in OSCA examples) and whether to filter per-sublibrary vs. pooled across the run are parameters, not defaults — proposing to tune these against your actual first dataset rather than hard-coding a number now.

06 · Suggested next steps

Proposed downstream stages, in depth

Ordering confirmed. Expanded below with the specific methods worth considering at each stage, following the papers you flagged.

  1. Normalization: log-normalization (counts per 10k, log1p) as the scanpy default; revisit Pearson-residual-based methods only if overdispersion looks like a real problem in the first dataset.
  2. Feature selection / dimensionality reduction: standard variance-stabilized HVG selection into PCA3 as the default. If cell-type labels already exist for part of a run (e.g. an annotated pilot sample), CellMentor's supervised, cell-type-aware NMF is worth a look as an alternative to plain PCA — it folds known labels into the embedding itself rather than discovering structure blind, which the authors show improves separation of closely related types and detection of rare populations9. Plain PCA stays the default until there's a labeled reference to supervise with.
  3. Batch integration: only needed once multiple sublibraries/samples run together — Harmony (R-side, pairs naturally with Seurat) or scVI (Python-side); decide once a real multi-sample run exists.
  4. Clustering: graph-based Leiden with a resolution scan as the default. If a run grows into the hundreds-of-thousands-of-cells range, standard Leiden's pairwise-similarity graph gets slow — scHashFormer's hash-based neighbor selection reports up to ~100× faster clustering on that scale while preserving trajectory and batch-integration validity6; worth revisiting only if runtime actually becomes a bottleneck, not by default.
  5. Marker detection & annotation: pairwise marker detection (Seurat FindMarkers / OSCA-style effect-size ranking), then reference-based or marker-based annotation. One methodological note worth keeping in mind for differential expression specifically: pseudobulk aggregation-then-test approaches have been shown to control false-discovery rate more reliably than naive per-cell tests, which treat each cell as an independent sample when cells from the same biological replicate aren't independent7 — worth adopting once we're comparing conditions/groups rather than just ranking markers within one dataset.
  6. Foundation-model / transformer annotation — flagged, not adopted: transformer-based annotation (e.g. scBERT-style models) is an active area, but a reusability audit found performance highly sensitive to cell-type class imbalance in the training data8 — directly relevant given how uneven cell-type abundances typically are in real tissue. Not adopting this now; noting it so it isn't reached for casually later without addressing that failure mode first.
  7. Cell-type-specific co-expression (optional, post-annotation): once clusters are annotated, cell-type-specific co-expression inference10 is a reasonable next layer for questions about regulatory structure within a type — scoped as optional, only if a specific biological question calls for it.
  8. Cell-cell communication (optional, post-annotation): CellChat infers ligand-receptor signaling between annotated cell types from the same processed object11; a broader survey of methods and databases (CellPhoneDB, NATMI, Omnipath, CellTalkDB) is useful context if CellChat's curated database turns out not to cover a pathway of interest12. Also optional/question-driven, not a default pipeline stage.
  9. Phase 2 — TCR/VDJ integration: when the TCR module is scoped, TRIM (TCR-RNA Integrating Model) is directly relevant — a multimodal VAE joining GEX and TCR data, with the notable finding that clonal identity, not the specific TCR sequence, drives most of the recoverable RNA–TCR relationship13. Worth reading before designing the TCR module's architecture, not before.

Default path vs. optional branches

Steps 1–5 are the pipeline as it will actually be built first. Steps 6–9 are flagged for when a specific need arises — they're documented now so the decision to reach for them (or not) is deliberate rather than default-by-inertia.
